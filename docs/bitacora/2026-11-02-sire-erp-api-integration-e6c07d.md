## 2026-11-02 (Comparar con SUNAT: la propuesta del SIRE contra el ERP, ADR-0601)
Qué hice: investigué la API del SIRE (`docs/investigacion/2026-11-02-sire-api-al-erp.md`) y, con el OK de Felipe, construí en 5 actividades Finanzas ▸ Impuestos ▸ Comparar con SUNAT: subir la propuesta de compras o de ventas (txt o .zip) y cruzarla con el registro del contador; resolver y deshacer cada diferencia; avisarlas en «Antes de declarar» y en el Cierre de mes (sin bloquear); y un cron que trae la propuesta sola por la API del SIRE, solo para leer.
Por qué así: el valor está en comparar ANTES de que el contador acepte la propuesta (IGV que no se descuenta, gastos sin registrar, el RUC usado por otro), no en presentar el SIRE desde el ERP: «generar» no está en la API y subir archivos pide Java. Las credenciales viven en variables de entorno, nunca en la base, y el cruce es uno solo para la pantalla, Impuestos y el cierre.
Qué se rompería sin esto: el contador seguiría aceptando la propuesta a ciegas y nadie vería una factura sin registrar o una anulación que no llegó a SUNAT hasta una fiscalización.
Felipe se lleva: (1) pegar en producción las migraciones `20261102202000`, `…203000` y `…204000`, en orden y cada una sola; (2) crear en SOL un usuario secundario solo para el SIRE, sacar sus credenciales de API y ponerlas en Vercel (Production): sin ellas todo funciona subiendo el archivo a mano; (3) subir una propuesta real de octubre para confirmar las columnas (el lector se escribió con las del anexo de SUNAT y nunca vio un archivo real); (4) en local quedaron mis propuestas de prueba de octubre 2026 (compras y ventas) en la base compartida.
